# Tenant Isolation

Tenant isolation is the most critical security boundary in ForgeOS. A tenant represents a distinct organization or billing entity.

## Mandatory Isolation
Every context retrieval operation **must** be tenant-aware. The `TenantID` must be hard-coded into the base of every database query and search request generated by the Context Engine. 

- **No Fallback**: If a query fails to find context, the fallback query must *never* omit the tenant scope.
- **Default Deny**: Cross-tenant retrieval is impossible by default. There is no legitimate use case in the standard ForgeOS operating model where Agent A (Tenant 1) should read code or memory from Tenant 2.

## Implementation Concept
At the infrastructure layer, this is enforced via Row-Level Security (RLS) in PostgreSQL. Even if a bug in the Context Engine's ranking logic attempts to fetch Tenant 2's data, the database will return an empty set.
