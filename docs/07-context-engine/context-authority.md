# Context Authority

Context Authority determines *how much an agent should trust* a piece of information. When resolving conflicts, Authority is the primary tie-breaker.

## Authority Levels

Levels are ordered from absolute truth to lowest trust.

1. **SYSTEM**: Hardcoded ForgeOS instructions. An agent can never override these.
2. **HUMAN_APPROVED**: Explicit decisions, overrides, or approvals provided by a verified human operator.
3. **APPROVED_ARTIFACT**: Formally merged Architecture Decision Records (ADRs) and Product Requirement Documents (PRDs).
4. **PROJECT_POLICY**: Broad rules configured in the Project Settings.
5. **TOOL_OUTPUT**: Objective facts observed from the environment (e.g., the output of a compiler, a test failure log).
6. **MEMORY**: Verified, distilled knowledge from the Memory Engine.
7. **AGENT_OUTPUT**: Decisions or code generated by a peer AI agent that has not yet been verified by a human or test suite.
8. **HISTORICAL**: Old conversations, stale branches, superseded requirements.
9. **INFERENCE**: Guesses made by the agent during its own reasoning loop.
10. **UNTRUSTED_DATA**: External web pages, unsanitized third-party API payloads.

## The Prime Directive of Authority
**An agent inference must never override an approved architecture decision.**

If an agent's internal model weights suggest using MongoDB, but the Context Package contains an `APPROVED_ARTIFACT` stating "This project strictly uses PostgreSQL", the agent must adhere to PostgreSQL. The Context Engine structures the prompt to enforce this hierarchy explicitly.
