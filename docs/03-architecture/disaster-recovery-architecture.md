# Disaster Recovery Architecture

In the event of a catastrophic failure, ForgeOS must protect user data and project state.

## RPO and RTO
- **Recovery Point Objective (RPO)**: The maximum acceptable data loss is 5 minutes (based on RDS snapshot frequency and WAL archiving).
- **Recovery Time Objective (RTO)**: The system should be back online within 1 hour via automated Infrastructure-as-Code (Terraform) pipelines.

## Recovery Strategies
- **Database Backups**: Automated daily snapshots and continuous WAL archiving to S3.
- **Project State Recovery**: Because artifacts and code are continuously committed to the external Git repository, even if the ForgeOS database is lost, the actual software products generated by the agents remain safe in GitHub/GitLab.
- **Workflow Rehydration**: If the core API crashes mid-task, the Workflow Engine uses its durable state in Postgres to resume the exact step it was on upon restart.
