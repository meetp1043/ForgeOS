# User Personas

### 1. Alex - The Indie Hacker (Individual Developer)
- **Role**: Solo Developer
- **Background**: Self-taught web developer who builds SaaS tools.
- **Technical skill**: Intermediate (strong in JS/React, weak in DevOps).
- **Goals**: Launch two micro-SaaS products this year.
- **Pain points**: Gets bogged down configuring AWS and writing backend boilerplate.
- **Typical workflow**: Works late nights, relies on Next.js, deploys to Vercel.
- **Current tools**: VS Code, GitHub Copilot, Vercel, Supabase.
- **ForgeOS expectations**: Wants ForgeOS to handle the entire backend and database schema based on a simple prompt, allowing them to focus entirely on the UI and marketing.
- **Success criteria**: Can launch a fully functional app in 48 hours instead of 3 weeks.

### 2. Sarah - The Non-Technical Founder (Startup Founder)
- **Role**: CEO/Founder
- **Background**: Domain expert in logistics, no coding experience.
- **Technical skill**: Low.
- **Goals**: Build an MVP for a logistics routing platform to secure seed funding.
- **Pain points**: Engineering agencies quoted $100k+ for the MVP; cannot afford a CTO yet.
- **Typical workflow**: Writes business plans, talks to customers, creates wireframes in Figma.
- **Current tools**: Notion, Figma, Slack.
- **ForgeOS expectations**: Needs to converse with an AI Business Analyst to define the product, and have the system build a working MVP that she can test with beta users.
- **Success criteria**: Has a working, bug-free prototype deployed to the web within a week, costing under $500 in AI tokens.

### 3. David - The Enterprise Architect (Engineering Manager)
- **Role**: Principal Engineer / Architect
- **Background**: 15 years in enterprise software, manages a team of 40 developers at a mid-sized bank.
- **Technical skill**: Expert (Java, Spring, Kubernetes, Security).
- **Goals**: Modernize a monolithic legacy application into modular services securely.
- **Pain points**: Developers are slow to adopt new security standards; code reviews take days; high risk of regressions.
- **Typical workflow**: Reviews architecture proposals (ADRs), audits security compliance, unblocks teams.
- **Current tools**: IntelliJ, Jira, GitHub Enterprise, SonarQube, AWS.
- **ForgeOS expectations**: Wants to use ForgeOS to enforce architectural boundaries. Expects AI Reviewer agents to automatically block PRs that violate the company's security baseline or introduce tech debt.
- **Success criteria**: AI handles 80% of routine code reviews accurately; zero critical security vulnerabilities reach production.
