# Workspace Model

The conceptual Workspace is the isolated environment where ForgeOS agents operate for a specific project. 

## Contents of a Workspace
A workspace contains all physical and logical assets required for the project:
- **Source Code**: The actual application code generated by the agents.
- **Documentation**: READMEs, PRDs, and ADRs.
- **Configuration**: Environment variables (securely injected) and project settings.
- **Infrastructure**: Terraform, Dockerfiles, and CI/CD scripts.
- **Tests**: Automated test suites.
- **Generated Artifacts**: Compiled binaries or builds.
- **Project Memory**: The vector database or graph containing past context and decisions.
- **Agent Outputs**: Execution logs and temporary scratchpads.

## Isolation and Boundaries
- **Strict Isolation**: A workspace is a secure boundary. Agents operating in Workspace A have absolutely no access to the files, memory, or context of Workspace B.
- **Filesystem Mapping**: The workspace maps to an isolated directory on disk or an ephemeral container.
- **Tool Confinement**: Tools granted to agents (e.g., `run_command`, `write_file`) are strictly chrooted/confined to the boundaries of the workspace.
