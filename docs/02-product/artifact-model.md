# Artifact Model

Artifacts are the persistent, tangible outputs generated by ForgeOS agents. They form the source of truth for the project.

## Types of Artifacts
- **Requirements**: Product Requirements Documents (PRDs), user stories.
- **Architecture Documents**: System designs, Architecture Decision Records (ADRs), data models.
- **Source Code**: The actual application files (e.g., `.java`, `.ts`, `.css`).
- **Tests**: Unit, integration, and e2e test files.
- **Database Migrations**: SQL scripts or ORM files (e.g., Flyway/Liquibase).
- **Infrastructure Definitions**: Dockerfiles, Terraform scripts, K8s YAML.
- **Deployment Manifests**: CI/CD pipeline definitions (e.g., `.github/workflows`).
- **Reports**: Incident reports, status summaries, security audits.
- **Review Results**: Feedback generated by the Reviewer agent.
- **Documentation**: READMEs, API specs (OpenAPI), user guides.

## Artifact Lifecycle
1. **Drafting**: Agent creates a temporary version in a scratchpad.
2. **Review**: The draft is evaluated against requirements and governance rules.
3. **Approval**: A human or Reviewer agent signs off.
4. **Publishing**: The artifact is committed to the Git repository or saved to the workspace.
5. **Evolution**: Artifacts are continuously updated as the project changes (e.g., docs update when code changes).
